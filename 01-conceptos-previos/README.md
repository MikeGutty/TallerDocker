# 01 — Conceptos previos

Antes de tocar Git, Docker o GitHub Actions, hay tres habilidades "invisibles" que todo el taller asume. No son tecnologías nuevas, pero si fallan, todo lo demás se traba. Esta carpeta las cubre en tres bloques cortos (5-10 min cada uno).

## Contenido

1. [`01-terminal.md`](./01-terminal.md) — Moverse por la terminal sin miedo
2. [`02-yaml.md`](./02-yaml.md) — Leer y escribir YAML sin errores de indentación
3. [`03-que-es-un-pipeline.md`](./03-que-es-un-pipeline.md) — El concepto de pipeline de CI/CD, sin código

## Por qué van aquí y no más adelante

- La **terminal** es necesaria desde el primer comando de Git (`git clone`, `git status`)
- El **YAML** es el lenguaje en el que se escribe todo GitHub Actions; si no se entiende antes, el primer workflow se vuelve un ejercicio de copiar y pegar sin comprensión
- El concepto de **pipeline** le da sentido a por qué existen Actions, antes de ver la sintaxis

## Cómo usar esta sección en el taller

Para quienes ya tienen experiencia, esto es un repaso de 2 minutos. Para quienes son principiantes, puede ser la diferencia entre seguir el resto del taller con fluidez o sentirse perdidos desde el minuto 20.

**Sugerencia:** antes de empezar, pregunta en voz alta quién ya se siente cómodo con la terminal. Así ajustas el ritmo de esta sección sin aburrir a nadie.

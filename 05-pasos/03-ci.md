# Paso 3 — Primer workflow de CI

**Tag de referencia:** `paso-3-ci`

## Objetivo

Crear el primer workflow de GitHub Actions: que corra lint y tests automáticamente en cada push o Pull Request.

## Qué hacer

1. Instala las dependencias en `04-app/` (esto genera el `package-lock.json` y descarga ESLint): `cd 04-app && npm install`, y confirma el lockfile con `git add`.
2. Prueba el lint localmente antes de subirlo: `npm run lint`. Si quieres ver un error real, rompe algo a propósito (ej. declara una variable y no la uses) y vuelve a correr `npm run lint`.
3. Revisa el workflow ya creado en [`.github/workflows/ci.yml`](../.github/workflows/ci.yml). Analiza cada sección:
   - `on`: qué eventos disparan el workflow (`push` y `pull_request` a `main`)
   - `jobs.build-and-test.runs-on`: la máquina virtual donde corre
   - `defaults.run.working-directory`: por qué apuntamos a `./04-app`
   - `steps`: cada acción en orden (`checkout`, `setup-node`, `install`, `lint`, `test`)
4. Haz un `git push` y ve a la pestaña **Actions** del repositorio para ver el workflow corriendo en vivo.
5. **Ejercicio de depuración:** el instructor romperá la indentación del YAML a propósito. Identifica el error leyendo el mensaje que da Actions y corrígelo.

## Cómo verifico que funcionó

- Al hacer push o abrir un PR, el workflow aparece corriendo en la pestaña **Actions**
- El workflow termina en verde (✅ success)
- Si rompes un test a propósito, el workflow falla (❌) y el PR lo marca como check fallido

## Reto avanzado

Agregar una matrix de versiones de Node para correr los tests en 22.x y 24.x a la vez:

```yaml
strategy:
  matrix:
    node-version: ["22", "24"]
steps:
  - uses: actions/setup-node@v4
    with:
      node-version: ${{ matrix.node-version }}
```
